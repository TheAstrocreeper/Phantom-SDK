# Experimental continuous stream

This isolated experiment compares a rolling-credit continuous sender with the SDK distribution implementation. It is not a production protocol. The sender transmits a manifest, verifies source chunks, and sends an indexed 64 KiB payload while data-channel buffering and a rolling 128-chunk commit window bound outstanding work. The receiver verifies each chunk and commits it to the SDK memory store. The receiver acknowledges every 16 commits, rather than stopping after a batch. It does not provide resumability, authentication, or multi-peer distribution.

The browser experiment sends and verifies an entire 32 MiB file. SDK cases use 1 and 3 associations; the stream case uses 1, so the single-association pair isolates the transfer strategy more closely. All cases use 64 KiB chunks and the same memory store; this is not Android native storage. Both are paced by the actual WebRTC connection. Profiles use 80 ms artificial RTT, 15.6 Mbps shaping, and either 0 or 0.1% independent loss. Case order reverses in the second repeat. Results are controlled experiments and do not represent the user's network or prove phone speed. Failed or 90-second incomplete runs must not be reported as full transfers.
